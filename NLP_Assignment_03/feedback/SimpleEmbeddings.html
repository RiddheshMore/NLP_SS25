One Hot Encoding¶

Perhabs the simplest way to build word embeddings is by using one hot vectors. These are vectors with a length of $|V|$ where $V$ is our vocabulary (the types from our corpus). The vocabulary should be an alphabetically sorted list of types.

A one hot vector consists of mostly zeros with a single one at the index of the word in the vocabulary.

Example:

Assume we have the vocabulary ['a', 'dog', 'i', 'have']. Then the embedding for the word a would be $[1, 0, 0, 0]$. The embedding for the word i would be $[0, 0, 1, 0]$.

Training ¶

Classes 1, 2, and 3 have strong diagonal dominance, while class 4 is confused mostly with class 2 and 3 and class 5 is frequently misclassified as class 2. This suggests the model struggles with higher ratings.

Testing ¶

Here, all classes are confused with neighboring classes. This indicates overfitting as it fails to generalize.

Why? ¶

It happens because one-hot vectors don’t capture semantic similarity; e.g. 'good' and 'great'. There is frequent misclassification between close ratings (2 and 3) as one-hot models treat all labels as equally different.

TfIdf Encoding¶

Another way of creating word embeddings is to use tfidf embeddings.

For this we need a set of documents from which we create a tfidf matrix. The rows of the matrix correspond to the terms while the columns correspond to the documents (see Figure 6.8 in the chapter Vector Semantics and Embeddings). The embedding for a certain word is then the row corresponding to that word in the tfidf matrix.

We use the following equations to calculate the tfidf values:

$\mathrm{tfidf}(t, d) = \mathrm{tf}(t, d) * \mathrm{idf}(t, d)$
$\mathrm{tf}(t, d) = \mathrm{log}_{10}(\mathrm{count}(t, d) + 1)$
$\mathrm{idf}(t, d) = \mathrm{log}_{10}\frac{N}{\mathrm{df}(t)}$
$\mathrm{df}(t) = $ number of documents $t$ appears in


Rough outline of the algorithm to create a tfidf matrix:

  1. Start by building a term document matrix $TD$. Each entry in the matrix tells us how often a term $t$ appears in the document $d$. The rows are the documents, the columns are the terms.
  2. Apply the logarithm to the $TD$ matrix to create the $TD_{log}$ matrix of logarithmic counts: $TD_{log} = \mathrm{log}_{10}(TD + 1)$.
  3. Create a df vector $\vec{\mathrm{df}}$ from that matrix by counting the non zero elements in each column of the TF matrix (np.count_nonzero). This tells in how many documents each term appears.
  4. Create an idf vector $\vec{\mathrm{idf}}$ from the $\vec{\mathrm{df}}$ by applying the logarithm: $\vec{\mathrm{idf}} = \mathrm{log}_{10}\frac{N}{\vec{\mathrm{df}}}$
  5. Multiply each row of $TD_{log}$ by the idf value for that term.

 1from typing import List
 2from collections import Counter
 3import numpy as np
 4
 5class TfIdfModel(EmbeddingModel):
 6    
 7    def build_index(self, docs: List[List[str]]) -> None:
 8        '''
 9        Create an index for the vocabulary from the docs
10        
11        Args:
12            docs -- A list of documents where each document is a list of tokens
13        '''
14        self.index = dict()
15        
16        all_tokens = set()
17        for doc in docs:
18            for token in doc:
19                all_tokens.add(token)
20        sorted_tokens = sorted(all_tokens)
21        idx = 0
22        for token in sorted_tokens:
23            self.index[token] = idx
24            idx += 1
25    
26    def train(self, docs: List[List[str]]) -> None:
27        '''
28        Train our model with a list of documents
29        
30        Args:
31            docs -- A list of documents where each document is a list of tokens
32        '''
33        self.build_index(docs)
34        
35        num_docs = len(docs)
36        vocab_size = len(self.index)
37        
38        # Create an empty term document matrix
39        term_doc_matrix = np.zeros((num_docs, vocab_size))
40        
41        # Fill term document matrix with raw counts
42        for doc_idx, doc in enumerate(docs):
43            counts = Counter(doc)
44            for word, count in counts.items():
45                if word in self.index:
46                    term_doc_matrix[doc_idx, self.index[word]] = count
47                    
48        num_docs = len(docs)
49
50        # Apply log transform
51        td_log = np.log10(term_doc_matrix + 1)
52        
53        # Compute document frequency vector
54        df_vector = np.count_nonzero(term_doc_matrix, axis=0)
55        
56        # Compute idf vector
57        idf_vector = np.log10(num_docs / df_vector)
58        
59        # Multiply td_log matrix rows with idf vector
60        self.tfidf_matrix = td_log * idf_vector  # Broadcasting
61    
62    def embed(self, word: str) -> np.ndarray:
63        '''
64        Embed a word into our tfidf vector space
65        If the word is not in the index it will return None
66        
67        Args:
68            word      -- The word we want an embedding for
69        Returns:
70            embedding -- The tfidf embedding for the word
71        '''
72        if word not in self.index:
73            return None
74        
75        word_idx = self.index[word]
76        return self.tfidf_matrix[:, word_idx]  # return the column corresponding to the word
77        
78    def vector_size(self) -> int:
79        return self.tfidf_matrix.shape[0]

Discuss the performance of the TfIdf Embeddings for this task compared to the performance of the One Hot Embeddings. Which one is better? Why?

Performance comparison:

  • TfIdf embeddings perform better than One Hot embeddings for this text classification task.
  • In TfIdf, we give more weight to important words (words that are frequent in a document but rare across documents), whereas in One Hot encoding, every word is treated equally (just presence or absence).

Why TfIdf is better:

  • Captures importance: TfIdf considers how informative a word is for a document, which helps the classifier focus on meaningful signals rather than noise.
  • Reduces the effect of common words: Common words (like "the", "a", "is") have lower tf-idf values, preventing them from dominating the feature space.
  • Provides richer document representations: Instead of binary 0/1 information, TfIdf vectors have graded values, giving the model more nuanced input.
  • Helps generalization: Because the TfIdf matrix scales down the weight of frequent but unimportant words, the classifier is less likely to overfit to irrelevant terms.

Summary:
Overall, TfIdf embeddings result in higher accuracy and better generalization compared to One Hot embeddings|, making them a stronger choice for document classification tasks like this one.
